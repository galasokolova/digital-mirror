# Small talk для маски машины

Первая версия принимает одну распознанную реплику на английском языке и возвращает её класс и оценку уверенности. JavaScript выбирает короткий ответ из заранее написанных фраз и озвучивает его через существующий `MachineSpeech`. Классификатор не участвует в голосовании по утверждению.

## Классы первой версии

| Метка | Примеры | Поведение |
|---|---|---|
| `greeting` | “Hi”, “Hey there” | Короткое приветствие. |
| `thanks` | “Thanks”, “Thank you” | Короткий ответ на благодарность. |
| `surprise` | “Wow!”, “Oh wow” | Сдержанная реакция на удивление. |
| `filler` | “Um”, “Hmm”, “Uh” | Тишина по умолчанию. Отдельные нейтральные отклики можно проверить вживую. |
| `other` | “I don’t agree”, “What happened there?”, “Next please”, фрагменты видео | Тишина. |

Одинаковый текст может передавать разное намерение. Например, “Oh” без интонации лучше разметить как `filler`. Фраза “Oh wow” подходит для `surprise`. В первой версии используем только текст распознавания.

## План обучения

1. Собрать пилотную разметку. Начать с 25–40 разнообразных реплик на каждый из четырёх целевых классов и 60–100 примеров `other`. Включить реальные расшифровки с микрофона, обрывки слов, вопросы о видео, согласие и несогласие, кавычки и слова из речи самой маски. Для будущего CSV использовать поля `text,label,group_id,source`; для записи с одного сеанса использовать общий `group_id`. Хранить расшифровки без персональных данных.
2. Разделить данные на train, validation и test по группам. Варианты одной реплики, строки из одной сессии и почти одинаковые фразы должны оставаться в одном сплите. Оставить отдельные живые записи для финального теста. Проверить, что каждый сплит покрывает все классы.
3. Обучить две версии Logistic Regression с TF-IDF. Сравнить символьные n-граммы 2–5 и словесные 1–2 на validation. Сохранить TF-IDF и классификатор одним sklearn Pipeline в `models/intent_classifier.joblib`. Зафиксировать метки, версию зависимостей и правила разбиения.
4. На validation подобрать порог для голосового ответа. При низкой уверенности, пустом тексте, `other` или `filler` маска молчит. На test измерить macro F1, precision и recall по классам, матрицу ошибок и долю ложных голосовых реакций на `other`. Для пилота стремиться к максимум одной ложной реакции на 20 посторонних реплик и отдельно проверить, сколько настоящих приветствий и благодарностей пропущено. Порог выбирается до оценки на test.
5. Подключить отдельный маршрут `POST /intent/predict` рядом с существующим `POST /predict`. Из браузера передавать через Spring Boot только финальный текст ASR и получать метку и уверенность. Если intent-сервис или микрофон недоступен, основной сценарий NEXT → CONFIRM продолжает работать.
6. Проверить демонстрацию с реальным микрофоном. Не передавать модели распознанные фразы во время звучания видео и синтеза речи. Добавить паузу между откликами и сбрасывать запоздавший ответ при переходе к новому утверждению. Дать приоритет реплике после CONFIRM и сохранить её финальную фразу. Проверить приветствие до START, благодарность после раскрытия, молчание на фоне ролика и отсутствие повторных реакций на голос маски.

Первый практический шаг — собрать и разметить пилотный CSV. Примеры из таблицы задают правила разметки. Для оценки качества понадобятся новые фразы и реальные расшифровки.
